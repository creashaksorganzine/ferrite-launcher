# Microsoft sign-in

Ferrite uses the Microsoft consumer **device authorization flow**. Passwords and
MFA are entered in Microsoft's browser UI, never in Ferrite.

## Application setup (launcher developers)

You must supply an application/client ID belonging to your launcher:

1. Register an application in Microsoft Entra's App registrations portal.
2. Choose a supported account type that includes **personal Microsoft accounts**.
3. In Authentication, enable **Allow public client flows** for device-code login.
4. Copy the **Application (client) ID**, not the directory/tenant ID.
5. Ensure the application is permitted to use Xbox Live sign-in and Minecraft
   Services. A successful Entra registration alone does not guarantee Minecraft
   API access; Microsoft/Mojang may require third-party application approval.

This implementation requests `XboxLive.signin` from the `consumers` OAuth v2
endpoint. It is a public client: **do not create, embed, or ask users for a client
secret**. No redirect URI is used by the device-code flow. Do not copy a client ID
from the official launcher or another third-party launcher.

The client ID can be entered in Ferrite's Account window or supplied through the
`FERRITE_MICROSOFT_CLIENT_ID` environment variable before starting Ferrite. The ID
is public configuration, not an access token. For a distributed release, launcher
maintainers should provide their own approved client ID rather than expecting
players to register an application.

## Signing in

1. Open **Play → Sign in / Account** (also available in Settings).
2. Enter your application's client ID if it was not supplied by the environment.
3. Click **Start Microsoft sign-in**.
4. Open the Microsoft verification link and enter the displayed code. Only use a
   code generated by your own sign-in attempt; do not share it with other people.
5. Complete browser sign-in using the Microsoft account with Minecraft Java
   Edition ownership or an eligible subscription and an initialized Java profile.
6. Wait for Ferrite to show your Minecraft username, then launch an instance.

Ferrite exchanges Microsoft → Xbox Live → XSTS → Minecraft tokens and checks the
Java entitlement and Minecraft profile. UI launches require a valid account; an
expired or failed sign-in does not silently fall back to placeholder credentials.

## Session and privacy behavior

- Sign-in, polling, and token exchanges run on a worker thread.
- Tokens stay in process memory: no account/token JSON, refresh token, or client
  secret is written to disk. Sign in again after restarting or when the session
  expires. Persistent OS-keyring storage and automatic refresh are not implemented.
- Cancel, closing the sign-in window, and sign-out discard pending results.
  In-flight HTTP calls can take up to their 15-second timeout to stop.
- Sign-out forgets Ferrite's credentials. It does not revoke Microsoft's issued
  token or terminate an already running Minecraft process.
- Ferrite does not log tokens or resolved launch arguments. Minecraft receives
  its access token in its standard launch arguments; local process-inspection
  tools, the game, and installed mods may be able to access it.
- Authentication contacts `login.microsoftonline.com`,
  `user.auth.xboxlive.com`, `xsts.auth.xboxlive.com`, and
  `api.minecraftservices.com`. The browser verification link is provided by
  Microsoft. No authentication data is sent to Modrinth.

## Troubleshooting

- **Rejected application/client:** check the Application ID, personal-account
  support, public-client flows, and the application's Xbox/Minecraft API access.
- **Xbox profile missing:** sign in at https://www.xbox.com/ to initialize it.
- **Family/age/region restrictions:** resolve the restriction in Microsoft/Xbox
  account settings; Ferrite cannot bypass these controls.
- **No Java entitlement/profile:** use the owning Microsoft account and initialize
  the Java player name/profile at https://www.minecraft.net/.
- **Expired device code or session:** start a new sign-in attempt.

## Validation

Offline tests cover OAuth responses, polling/backoff, cancellation, entitlement
and profile parsing, Xbox claims, UI worker lifecycle, and launch placeholders.
An end-to-end sign-in requires a configured application ID and interactive account
approval; neither can be supplied by the automated test suite.
